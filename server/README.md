# Сервер и база данных

## Что внутри
- `server.js` — WebSocket-сервер + SQLite (`better-sqlite3`). Протокол совпадает с клиентом игры:
  `login` → `login_success`, `move`, `players_list`, `chat`, `error`, `save` (запись текущего баланса), `set_plate`;
  поля `car_id` / `car_number` / `token` (привязка ника к устройству).
- `colab_setup.py` — ячейка Colab: монтирует Google Диск, ставит зависимости, поднимает сервер и ngrok-туннель.
- `live.json` — **актуальный адрес сервера для клиента**: его читает `src/game/discovery.ts`, поэтому игрок адрес не вводит.
- `colab_admin.py` — **мини админ-панель в выходной ячейке Colab**: кнопки для денег, бана, кика, телепорта, выдачи машины и объявлений. В самой игре никакой админки нет.

## Быстрый старт в Colab
1. Загрузите `server.js` в `MyDrive/MyGame/`.
2. Откройте новую ячейку и вставьте код из `colab_setup.py`, впишите токен ngrok.
3. Ничего копировать не нужно: игроки заходят по постоянной ссылке, адрес сервера клиент находит сам
   (см. раздел ниже). Для проверки панель показывает и служебную ссылку `?srv=…`.

## Одна постоянная ссылка для игроков
Сайт игры не меняется никогда: `https://dimastwa0sopsi.github.io/File/` — игрок открывает его и жмёт «▶ Играть».
Меняется только адрес туннеля, поэтому сервер сам записывает его в `server/live.json` этого репозитория:

1. В Colab-панели (последняя ячейка) заполните поле **GitHub** — токен с правом `contents: write`
   (Settings → Developer settings → Personal access tokens → Fine-grained → Contents: Read and write).
2. Нажмите **📡 Постоянная ссылка** — сервер сделает `GET /admin/publish?token=…`, тот возьмёт адрес
   туннеля (`PUBLIC_URL` → API ngrok на 4040) и обновит `server/live.json` через GitHub API.
3. Тот же запрос выполняется автоматически при старте сервера, если задан `GH_TOKEN`.

Дополнительно можно взять **статический домен ngrok** (бесплатный тариф — один домен): впишите его в поле
«Домен» панели или в `NGROK_DOMAIN` в `colab_setup.py` — тогда адрес не меняется вообще и `live.json` не нужен.

Клиент пробует адреса по порядку: `?srv=…` → `live.json` (raw.githubusercontent → Statically → jsDelivr,
свежий `updated` первым) → сохранённый в браузере → вшитый `ONLINE_URL`. Каждый кандидат проверяется живым
WebSocket-подключением, поэтому мёртвый туннель пропускается, а не «залипает».

## Админ-панель в Colab
1. Запустите `colab_setup.py` — он поднимет сервер и запомнит `ADMIN_TOKEN` (по умолчанию `losgorod-admin`).
2. Создайте новую ячейку и вставьте содержимое `colab_admin.py`.
3. Управляйте кнопками:
   - **Деньги** — задать сумму или добавить (+10 000 / +100 000 / +1 000 000), списать всё;
   - **Модерация** — забанить (с причиной), разбанить, кикнуть;
   - **Телепорт** — отправить игрока на координаты X/Z или на точку появления (срабатывает сразу, если игрок в сети);
   - **Транспорт** — выдать машину и номерной знак;
   - **Объявления** — сообщение от СИСТЕМЫ в общий чат, очистка чата;
   - **Привязка устройства** — `🔓 Сбросить привязку устройства` (если игрок сменил телефон/браузер и не может войти под своим ником);
   - **Опасное** — удалить аккаунт (с подтверждением);
   - **Игроки** — таблица: статус, деньги, машина, координаты, бан.

Панель ходит в локальный HTTP-API сервера: `GET /admin/state` и `POST /admin/action` с `?token=...`.
Игра этот API не использует — права администратора в клиенте полностью убраны.

## Схема базы (SQLite)
| Таблица | Поля |
|---|---|
| `players` | id, name (уникальный), gender, money, car_id, car_number, house_id, pos_x, pos_z, pos_rot, token, banned, ban_reason, updated_at |
| `chat_log` | id, name, text, t |

## Аккаунты и деньги
- **Один ник — один аккаунт.** При первом входе сервер выдаёт нику случайный `token` и запоминает его; клиент хранит токен в браузере.
  Вход под чужим ником с другого устройства отклоняется с понятным текстом. Сброс — кнопкой `🔓 Сбросить привязку устройства`.
- **Один ник — одна сессия.** Второй вход под тем же ником в сети отклоняется, чтобы два игрока не «перетягивали» аккаунт.
- **Никакого слияния денег.** Баланс онлайна живёт только в базе: при входе клиент получает серверный баланс и сразу записывает его в свой онлайн-сейв.
  Локальный соло-кошелёк в онлайн не переносится, поэтому старые суммы не «переезжают» на новый ник.
- **Новый аккаунт** создаётся со стартовым капиталом `$20 000` (колонка `money` в таблице `players`, значение по умолчанию).
  Изменить баланс можно только через админ-панель (`💵 Деньги`), после чего клиент получит новую сумму с сервера.
- Изменения денег в игре (зарплаты, покупки) клиент присылает сообщением `{type:'save', money}`, сервер пишет их в базу —
  это не слияние, а обычная запись текущего баланса, чтобы заработок в онлайне не пропадал.

## Почему SQLite на Google Диске — рабочий вариант
- База — один файл `game.db` в `MyDrive/MyGame`, поэтому данные не теряются при перезапуске Colab.
- WAL-режим + запись `move` на каждое сообщение даёт до ~15 записей/сек на игрока; для 10–20 игроков это нормально.
- Если игроков станет больше, база легко переносится в Postgres (Supabase) — структура таблиц та же, меняется только драйвер.
- Токен ngrok храните приватно: с ним можно перехватить туннель.

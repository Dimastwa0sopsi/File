# Сервер и база данных

## Что внутри
- `server.js` — WebSocket-сервер + SQLite (`better-sqlite3`). Протокол совпадает с клиентом игры:
  `login` → `login_success`, `move`, `players_list`, `chat`, `error`, `save` (запись текущего баланса), `set_plate`;
  поля `car_id` / `car_number` / `token` (привязка ника к устройству).
- `colab_cell.py` — **вся ячейка Colab целиком**: Диск, скачивание `server.js` с зеркал, зависимости,
  сервер (старый процесс на порту заменяется по отпечатку `/version`), ngrok, публикация `live.json`
  и админ-панель (поиск игроков, карточка, 100 кнопок, чат, сервер и логи).
- `colab_setup.py` — тонкая обёртка для старых инструкций: скачивает и выполняет `colab_cell.py`.
- `live.json` — **актуальный адрес сервера для клиента**: его читает `src/game/discovery.ts`, поэтому игрок адрес не вводит.

## Быстрый старт в Colab
1. Загрузите `server.js` в `MyDrive/MyGame/`.
2. Откройте новую ячейку и вставьте код из `colab_cell.py`, впишите токен ngrok в `CFG`.
3. Ничего копировать не нужно: игроки заходят по постоянной ссылке, адрес сервера клиент находит сам
   (см. раздел ниже). Для проверки панель показывает и служебную ссылку `?srv=…`.

## Одна постоянная ссылка для игроков
Сайт игры не меняется никогда: `https://dimastwa0sopsi.github.io/File/` — игрок открывает его и жмёт «▶ Играть».
Меняется только адрес туннеля, поэтому сервер сам записывает его в `server/live.json` этого репозитория:

1. В Colab-панели (последняя ячейка) заполните поле **GitHub** — токен с правом `contents: write`
   (Settings → Developer settings → Personal access tokens → Fine-grained → Contents: Read and write).
2. Нажмите **📡 Постоянная ссылка** — сервер сделает `GET /admin/publish?token=…`, тот возьмёт адрес
   туннеля (`PUBLIC_URL` → API ngrok на 4040) и обновит `server/live.json` через GitHub API.
3. Тот же запрос выполняется автоматически при старте сервера, если задан `GH_TOKEN`.

Дополнительно можно взять **статический домен ngrok** (бесплатный тариф — один домен): впишите его в поле
«Домен» панели или в `NGROK_DOMAIN` в `colab_cell.py` — тогда адрес не меняется вообще и `live.json` не нужен.

Клиент пробует адреса по порядку: `?srv=…` → `live.json` (raw.githubusercontent → Statically → jsDelivr,
свежий `updated` первым) → сохранённый в браузере → вшитый `ONLINE_URL`. Каждый кандидат проверяется живым
WebSocket-подключением, поэтому мёртвый туннель пропускается, а не «залипает».

## Админ-панель в Colab
Панель строится той же ячейкой (`colab_cell.py`) и появляется под её выводом. В самой игре никакой админки нет.

1. Запустите ячейку — она поднимет сервер и запомнит `ADMIN_TOKEN` (по умолчанию `losgorod-admin`).
2. Работайте во вкладках панели:
   - **👥 Игроки** — поиск по нику, фильтр «все / в сети / офлайн / в бане», сортировка по нику, деньгам
     и варнам; карточка игрока; кнопки: деньги, вылечить, убить, заморозить, телепорт, выдать машину,
     номер, варн, мут, кик, бан и разбан;
   - **🎛 100 кнопок** — весь каталог `ADMIN_ACTIONS` из `server.js`, разложенный по 8 группам
     (деньги, модерация, телепорт, транспорт, чат, игрок, сервер, события);
   - **📢 Чат** — объявление от СИСТЕМЫ, лента сообщений, очистка чата;
   - **🖥 Сервер** — адрес туннеля и постоянная ссылка для игроков, публикация `live.json`, перезапуск,
     инфо/бэкап/размер базы, техработы, статистика и живые логи.

Общие поля (причина бана, X/Z, модель, номер, дом, текст объявления, галочка «Разрешить опасные действия»)
вынесены над вкладками: они нужны нескольким вкладкам сразу. Опасные действия без галочки не выполняются.
Подробности и таблица «что делать, если» — в `colab_cells.md`.
